# 真政治

公平、公正、透明地揭露台灣政治資訊的平台，讓所有人都能看到正確、可查證的資訊。

## 三個原則

1. **公正**：不偏袒任何政黨或人物，所有候選人用同一套標準與版面。
2. **可查證**：每一筆查核都附上公開來源。
3. **透明**：判定標準、資料格式與修改紀錄都公開。

## 第一版功能：辯論逐字稿查核

- 以 2026/10/31 臺北市長電視辯論（蔣萬安、沈伯洋）為第一場，收錄申論、四輪交叉詰問、媒體提問、結論的完整逐字稿。
- 逐字稿來源：ETtoday 新聞雲現場整理版，並與 NOWNEWS 今日新聞的交叉詰問全文交叉比對。
- 以對話形式呈現：依實際發言順序排列，兩位候選人的發言氣泡分在左右兩側並附頭像（可一鍵對調），主持人與媒體提問置中。
- **逐字稿的每一句都可以點開**：
  - 已查核的句子會劃線並標出判定，點開可看數據查核（正確／部分正確／錯誤／無法查證）、執行所需費用、實際會遇到的問題、公開來源連結。
  - 尚未查核的句子顯示「尚未查核」，並可一鍵建議查核（開 GitHub Issue）。
- 每位候選人的查核進度統計（總句數、各判定數、尚未查核數），可依判定篩選。

## 候選人像素頭像

`img/*.svg` 由 `tools/pixel_avatars.py` 產生：兩人共用同一個 24×24 臉部與西裝模板、同一組配色，只差在髮型與是否戴眼鏡，不美化也不醜化任何一方，配色不用政黨色。修改後執行 `python3 tools/pixel_avatars.py` 重新產生。

## 政黨黨徽

`img/party-*.svg` 由 `tools/party_logos.py` 依各黨標誌的基本幾何畫成像素版，兩黨用同樣的格數與處理方式。

## 單一檔案預覽

`python3 tools/build_preview.py 輸出.html` 會把資料、圖片、CSS、JS 全部內嵌成一個檔案，方便直接分享預覽。

## 怎麼看

網頁用 `fetch` 讀取 JSON，需要透過伺服器開啟（直接雙擊 `index.html` 會讀不到資料）：

```bash
python3 -m http.server 8000
# 打開 http://localhost:8000
```

純靜態網頁，不需要建置步驟，可直接部署到 GitHub Pages、Cloudflare Pages 等。

## 資料格式

```
data/
  index.json                      # 所有辯論的清單
  debates/
    2026-taipei-mayor-1.json      # 一場辯論一個檔案
```

### 新增一場辯論

1. 在 `data/debates/` 新增一個 JSON 檔（可複製現有檔案修改）。
2. 在 `data/index.json` 的 `debates` 加一筆 `{ id, title, date, file }`。
3. 執行 `node tools/validate.mjs` 檢查格式。

### 辯論檔欄位

| 欄位 | 說明 |
|---|---|
| `id`、`title`、`date`、`format` | 辯論基本資訊 |
| `isSample`、`sampleNote` | 是否為範例資料；為 `true` 時網頁會顯示提示 |
| `transcriptNote` | 逐字稿來源與比對說明，顯示在頁面上方 |
| `debateSources` | 辯論本身的公開來源（錄影、官方逐字稿） |
| `candidates` | `{ id, name, party }`，陣列順序就是預設的左右順序（建議依抽籤順序） |
| `sections` | 辯論環節 `{ id, title }`，依時間順序 |
| `utterances` | 發言段落 `{ id, speaker, section, label, text }`，依時間順序排列。`speaker` 為候選人 id，媒體提問用 `"press"`、主持人用 `"moderator"`；`label` 如「提問」「回答」「追問」；`text` 必須是逐字原文，換段用 `\n`。網頁會自動把每段切成句子 |
| `claims` | 查核項目，見下表 |

### 查核（`claims`）欄位

| 欄位 | 說明 |
|---|---|
| `id` | 唯一代號 |
| `speaker`、`utteranceId` | 發言人與所屬段落 |
| `quote` | 被查核的句子，必須與 `text` 中的文字**完全相同**，網頁會自動劃線 |
| `topic` | 議題（居住、交通、育兒、財政…） |
| `verdict` | `correct` 正確、`partly` 部分正確、`incorrect` 錯誤、`unverifiable` 無法查證 |
| `summary` | 一句話結論 |
| `analysis` | 查核過程與數據比對 |
| `cost` | `{ estimate, basis }` 執行費用估算與依據；對既有事實的陳述填 `null` |
| `challenges` | 實際執行會遇到的問題（字串陣列） |
| `sources` | `{ title, publisher, url }`，至少一筆 |
| `checkedAt` | 查核日期（`YYYY-MM-DD`），未正式查核為 `null` |

## 公正性做法

- 兩位候選人用各自政黨色與像素黨徽辨識（`candidates[].color`、`logo`），版面與處理方式完全相同；查核結果的顏色刻意避開兩黨的藍與綠。
- 判定標準公開於網頁上，所有發言適用同一套標準。
- 逐字稿每一句都可點開，不只預先挑選的句子；查核順序依同一個標準：先查含具體數字或可用公開資料驗證的事實陳述。
- 查核只針對可驗證的事實與數字，不評論立場。
- `tools/validate.mjs` 會列出每位候選人的查核筆數，差距過大時提醒檢查選題是否一致。

## 查核資料來源原則

- 優先使用官方資料：法務部全國法規資料庫、立法院、內政部不動產資訊平台、臺北市政府各局處與資料開放平臺、主計處預算與決算、審計部、國科會各科學園區管理局等。
- 官方未公開時，才引用媒體報導中引述官方的數字，並在查核中註明。
- 找不到可核對的公開資料就標示「無法查證」，並說明還缺什麼資料。
